# MUBU 광고 전략 설계서

> 유저 플로우별 광고 삽입 포인트, 비교 횟수 제한, 수익 모델 설계

---

## 1. 현재 유저 플로우

```
Home (촬영 버튼)
  → ImageSourceSheet (업로드/촬영 선택)
    → Analyzing (AI 분석 로딩)
      → PriceConfirm (상품명 + 출처: 쿠팡 + 가격 + 맞아요/수정)
        → Result (가격 비교 테이블 + 절약 금액 + 한국가격 보기/구매)
```

### 문제점
- PriceConfirm에서 **"출처: 쿠팡"** + **상품명**이 바로 노출됨
- 유저가 쿠팡에서 직접 검색 가능 → 광고를 볼 이유 없음
- 광고 삽입 지점 없음

---

## 2. 개선된 유저 플로우 (광고 포함)

```
Home (촬영 버튼)
  → ImageSourceSheet (업로드/촬영 선택)
    → Analyzing (AI 분석 로딩)
      → [NEW] AdGate (전면 광고 게이트)
        → PriceConfirm (상품명 + 출처 + 가격 확인)
          → Result (가격 비교 + 하단 배너 광고 슬롯)
```

### 라우팅 변경

| Before | After |
|--------|-------|
| `/analyzing` → `/price-confirm/:id` | `/analyzing` → `/ad-gate/:id` → `/price-confirm/:id` |

---

## 3. 광고 삽입 포인트

### 포인트 1: 전면 광고 게이트 (AdGate)

**위치:** Analyzing 완료 → PriceConfirm 진입 전

**방식:** 플랜 AI 참고 — 바텀시트로 "광고를 시청하면 가격 비교 결과를 볼 수 있어요" 안내 후 전면 광고

**구현:**
- 토스 환경: `GoogleAdMob.loadAppsInTossAdMob` → 바텀시트 확인 → `showAppsInTossAdMob` → `dismissed` 이벤트 → PriceConfirm 이동
- 일반 웹: 광고 없이 바로 PriceConfirm 이동 (skip)

**핵심:**
- 유저는 이미 사진 찍고 분석까지 기다린 상태 → 이탈보다 광고 시청 선택 가능성 높음
- "닫기" 누르면 홈으로 돌아감 (결과 못 봄)

**UI 구조:**
```
┌─────────────────────────┐
│                         │
│   분석이 완료되었어요!    │
│                         │
│  ┌───────────────────┐  │
│  │                   │  │
│  │  광고를 시청하면    │  │
│  │  가격 비교 결과를   │  │
│  │  볼 수 있어요      │  │
│  │                   │  │
│  │ [닫기] [결과 보기]  │  │
│  └───────────────────┘  │
│                         │
└─────────────────────────┘
```

### 포인트 2: Result 하단 배너 광고 슬롯

**위치:** Result 페이지 하단 (가격 비교 결과 아래, 면책 문구 위)

**방식:** 배너 형태 광고 슬롯 (비침습적)

**참고:** 토스 인앱 광고는 전면형/보상형만 제공 → 배너는 자체 제휴 또는 향후 확장용 자리만 마련

## 4. 비교 횟수 제한 로직

### 분기 구조

| 사용자 유형 | 일일 비교 횟수 | 광고 시청 | 비고 |
|-------------|---------------|-----------|------|
| 비로그인 | 3회 | 매 비교마다 전면 광고 | 로그인 유도 |
| 로그인 (무료) | 5회 | 매 비교마다 전면 광고 | 유료 전환 유도 |
| 유료 사용자 | 무제한 | 광고 없음 | 월정액 또는 패스 |

### 구현 위치
- **프론트엔드:** `usageStore` 또는 `priceStore` 확장 — 로컬 비교 횟수 카운트
- **백엔드:** 로그인 사용자는 서버에서 횟수 관리 (세션/DB)
- **체크 시점:** AdGate 진입 시 횟수 확인 → 초과 시 "오늘 비교 횟수를 모두 사용했어요" 안내

### 횟수 초과 시 UI

```
┌─────────────────────────┐
│                         │
│   오늘 비교 횟수를       │
│   모두 사용했어요        │
│                         │
│   보상형 광고를 시청하면  │
│   1회 추가 비교가        │
│   가능해요               │
│                         │
│ [홈으로] [광고 보고 1회+] │
│                         │
└─────────────────────────┘
```

→ 보상형 광고 (`ait-ad-test-rewarded-id`) 사용 → `userEarnedReward` 이벤트로 횟수 +1

## 5. PriceConfirm 출처 숨김 처리

### 현재
- `compareResult.mallName` ("쿠팡")이 상품명 바로 아래 노출
- 유저가 쿠팡 직접 검색 가능

### 변경
- 토스 환경: 광고 시청 완료 후에만 PriceConfirm 도달 → 출처 노출해도 OK (이미 광고 봤으니)
- 다만 출처를 강조하지 않도록 스타일 조정 (색상 흐리게, 폰트 작게)
- Result 페이지의 "한국가격 보기" 버튼이 실질적 가치 → 여기서 쿠팡 링크 노출

## 6. 플랜 AI 앱 참고 분석

### 플랜 AI 광고 플로우
1. 도시 선택 → 기간 선택 → 타입 선택 (3단계 투자)
2. **ConfirmDialog:** "광고를 시청하면 AI 여행 일정을 생성할 수 있어요" → [닫기] [일정 생성하기]
3. 전면 광고 재생 (미로 게임 등)
4. 로딩 화면 (텍스트 변경 애니메이션)
5. 결과 페이지

### MUBU에 적용할 점
- **타이밍 동일:** 유저가 시간을 투자한 후 (사진 촬영 + 분석 대기) 광고 삽입
- **ConfirmDialog 패턴:** TDSDialog (ConfirmDialog) 사용 — "닫기" + "결과 보기"
- **차이점:** 플랜 AI는 미로 게임 전면 광고 → MUBU는 Google AdMob 전면 광고

## 8. 구글 애드몹 정책 준수 사항

- 토스 인앱광고는 **구글 애드몹 광고 정책**을 따름
- 핵심 플로우 (결제/가입/로그인) 중에는 광고 노출 금지
- 사용자에게 과도한 광고 노출 금지
- 광고 재생 중 앱 사운드 일시 정지 → 광고 끝나면 자동 재생

---

## 9. 수익 구조 요약

```
전면 광고 (매 비교 시)
  → eCPM 기반 수익 (1,000회 노출당 수익)
  → 예: eCPM 60,000원 × 300회 노출 = 18,000원/일

보상형 광고 (횟수 초과 시)
  → 추가 비교 1회 제공
  → 유저 리텐션 + 추가 수익

쿠팡 파트너스 (기존)
  → "한국가격 보기" / "구매함" 클릭 → 쿠팡 링크
  → 구매 시 수수료 수익
```
